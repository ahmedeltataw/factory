## Scope

In M7 the Supervisor limits how much work it starts: (1) a **parallel slot cap** per project, (2) a **quota ledger** per provider window with reserve before dispatch, settle after, release on failure, (3) **budget caps** at project, phase and task level with 70% / 90% / 100% thresholds, (4) **intake budgets** per actor per day (closes the M6 residual). All are visible in `status` and set by CLI commands.

Out of M7: real provider usage parsing (token events per CLI, M8+ adapters), model fallback and role allocation (the 90% threshold is only a recorded state, no model switch), a global quota manager shared across projects (one Supervisor per project; the ledger is per project), cost in money, auto-resume after quota (manual by default), Lead Brain calls, any GitHub write.

**Unit.** One unit is one started attempt. Providers do not report usage yet, so every number is `source: counted`, never shown as remaining tokens.

## Frozen interfaces

### Schema v9 (`store.ts`)

- `project_limits(project_id PK → projects, max_parallel INTEGER NOT NULL CHECK (max_parallel >= 1), updated_at)`: no row = no cap.
- `quota_windows(project_id, provider TEXT, window_ms INTEGER CHECK (>= 1000), max_units INTEGER CHECK (>= 1), updated_at, PK(project_id, provider))`: no row = unlimited for that provider.
- `quota_reservations(id PK, project_id, attempt_id UNIQUE → attempts, provider, units INTEGER CHECK (= 1), state CHECK IN ('reserved','settled','released'), reserved_at_ms, closed_at_ms)`: state moves only reserved → settled | released; rows are never deleted.
- `budget_caps(project_id, level CHECK IN ('project','phase','task'), key TEXT ('' for project), cap_units INTEGER CHECK (>= 1), updated_at, PK(project_id, level, key))`.
- `tasks.provider TEXT NOT NULL DEFAULT 'default'` (added column; old rows get `default`).
- Usage is always derived (count of `reserved` + `settled` reservations joined to tasks), never a stored counter.

### Slots and gates (`core/graph.ts`, pure)

`DispatchInput` gains optional `maxParallel: number | null` and `gates: Record<string, 'quota' | 'budget'>`. `WaitReason` gains `'slots' | 'quota' | 'budget'`. In `planDispatch`, after the backoff check and before schedule: a task in `gates` waits with that reason (`on: []`), then if `running + scheduled >= maxParallel` it waits `slots` with `on` = the progress tasks. `running` = tasks in `progress`. Waiting for gates or slots does not join `held`. Absent `maxParallel` and `gates` give the M6 plan exactly.

### Ledger (`app/quota.ts`)

- `reserve(db, handle, taskId, nowMs): { ok: true; reservationId } | { ok: false; reason: 'quota' | 'budget'; retryAtMs: number | null }`: checks the provider window (reservations with `reserved_at_ms > nowMs - window_ms` in state reserved or settled, plus the new one, ≤ `max_units`), then the three budget caps (task, phase, project). On success inserts a `reserved` row. `retryAtMs` = when the oldest counted reservation leaves the window (quota) or `null` (budget: a person must raise the cap).
- `settle(db, handle, attemptId, nowMs)`: attempt reached `succeeded`, `failed` or `interrupted` after it started a worker → `settled`. `release(...)`: the attempt never started a worker (outbox failure, `superseded`, killed while `pending`) → `released`, no usage counted.
- Window boundary: a reservation made exactly `window_ms` ago no longer counts.
- Thresholds: `usagePct = floor(100 * used / cap)` per cap; `warn` ≥ 70, `fallback-needed` ≥ 90, `stop` = 100 (dispatch gate `budget`). A cap lowered below current usage stops dispatch, never kills running work.

### Loop wiring (`supervisor-loop.ts`)

In `dispatch-tasks`, `dispatchInput` adds `maxParallel` and the `gates` map (each ready task checked with a dry-run of the same limits `reserve` uses); for each `plan.schedule` id, `reserve` runs inside the same `fencedWrite` before `scheduleAttempt`; a failed reserve leaves the task `ready` (no status change). `runTick` idle rule: `slots`, `quota` waits with a non-null `retryAtMs` keep the loop busy; `budget` waits and null `retryAtMs` do not (a person must act). Reconcile and worker-liveness call `settle`/`release` for every attempt they close.

### Intake budget (`sources/github/gate.ts`, `ingest.ts`)

Policy gets optional `maxPerActorPerDay` (1..1000, absent = no limit; policy `version` stays 1). `ingestPoll` counts `github_events` rows with that `actor_id` and `status` in `approved`/`pending` whose `received_at` is within 24 h of `nowMs`; at the limit the event is stored `rejected` with reason `actor-daily-limit` (never silently dropped).

### Commands (`commands.ts`, `apply-commands.ts`, `cli/main.ts`)

Append-only commands, applied by the Supervisor only: `limits set --max-parallel <n> | --clear-parallel`, `quota set --provider <p> --window-ms <n> --max-units <n> | quota clear --provider <p>`, `budget set --level project|phase|task [--key <k>] --cap <n> | budget clear ...`, and `task create --provider <p>` (new optional flag). Bad numbers, unknown phase or task keys are `rejected` with a named reason. Arabic human text, English identifiers.

### Status additions

`status --json` gains `limits: null | { maxParallel, running, waitingSlots }`, `quota: null | { windows: [{ provider, windowMs, maxUnits, used, resetsAt }] }`, `budget: null | { caps: [{ level, key, cap, used, pct, state: 'ok'|'warn'|'fallback-needed'|'stop', source: 'counted' }] }`. Each is `null` when its tables are empty (M6 status unchanged otherwise except `schemaVersion` 9). Waiting tasks show reason `slots`, `quota` or `budget`.
