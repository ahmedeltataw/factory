## Frozen interfaces

Tables (migration 5, one transactional step, same rules as M2: version re-check inside the write transaction, future versions refused unmodified):
- `project_config(project_id PK→projects, repo_path, base_ref, created_at)`
- `command_outcomes(command_id PK→commands, outcome applied|rejected, reason, lease_generation, applied_at)`, append-only
- `tasks(id PK, project_id→projects, created_by_command UNIQUE→commands, title, status, created_at, updated_at)`
- `attempts(id PK, task_id→tasks, attempt_no, UNIQUE(task_id, attempt_no), status pending|running|succeeded|failed|interrupted|killed, exit_code, error_class, lease_generation, started_at, ended_at)`, partial unique index: at most one `pending|running` attempt per task
- `workers(attempt_id PK→attempts, nonce UNIQUE, pid, state starting|running|exited|killed|lost, worktree_path, heartbeat_ms, started_at, ended_at)`
- `outbox(id PK, idempotency_key UNIQUE, kind, payload_json, status pending|done|failed, tries, next_attempt_ms, last_error, created_at, updated_at)`
- `evidence(attempt_id PK→attempts, base_sha, head_sha, files_json [{path, sha256}], stdout_sha256, stderr_sha256, recorded_at)`, immutable

Task status: `progress|waiting|ready|blocked|failed|dropped|done`.

Implementation conventions (frozen 2026-11-10, Lead; they continue what M2 `store.ts` already does, so protected tests may rely on them): the migration and `fencedWrite` acquire their write transaction with `db.exec('BEGIN IMMEDIATE')` and end it with `db.exec('COMMIT')` / `db.exec('ROLLBACK')`; each migration-5 DDL statement is a separate `db.exec(...)` call; enum columns are enforced with SQLite `CHECK` constraints; append-only tables use `BEFORE UPDATE` / `BEFORE DELETE` triggers that `RAISE(ABORT, ...)`.

CLI (exit codes stay 0 success / 1 failure / 2 arguments; Arabic messages):
- `factory init --state-dir <d> --repo <path>`: the one bootstrap writer (acquires the lease, creates DB, project and config, releases).
- `factory task create --state-dir <d> --title <t> [--command-id <uuid>]`
- `factory task kill --state-dir <d> --task <id> [--command-id <uuid>]`
- `factory start --state-dir <d> [--exit-when-idle] [--takeover <ownerId>:<generation>:<heartbeatMs>] [--stale-after-ms n] [--heartbeat-ms n]`
- `factory status …` (existing). Task commands only append `commands` rows.

Fault injection: env var `FACTORY_FAULT`, read only at the CLI entry and passed as an option. Values `outbox-before-effect`, `outbox-after-effect`, `attempt-after-spawn`; unknown value exits 2. A fault terminates the process at once (no `finally`, no exit handlers).

Worktree: `<stateDir>/worktrees/<taskId>` on branch `factory/task/<taskId>` from `base_ref`. Run dir: `<stateDir>/runs/<attemptId>/` with `worker.json` (pid, nonce, written by the executor at startup), `stdout.log`, `stderr.log`, and `result.json` (`{"exitCode": <int>}`, written atomically by the executor via temp file + rename as its last step before a normal exit; absent if the executor was killed or crashed). Attempt completion is read from `result.json`, never from the process exit status, because after a Supervisor restart the executor is not its child: worker dead + `result.json` → attempt `succeeded` (exitCode 0) or `failed`; worker dead + no `result.json` → worker `lost`, attempt `interrupted`. (Lead amendment 2026-11-10, found in M3-06 test review.)

Command apply semantics (frozen 2026-11-10, Lead, after test review):
- `task.create` payload `{ "title": string }`; the created task's `id` equals the command `id`; status `ready`.
- `task.kill` payload `{ "taskId": string }`. On a task in `ready|waiting|blocked|progress`: task status becomes `dropped` in the same fenced transaction, and for each of its `pending|running` attempts an outbox row is enqueued with kind `attempt.kill`, idempotency key `attempt.kill:<attemptId>`, payload `{ "attemptId": string }`. On a task in `done|failed|dropped` or an unknown task: outcome `rejected`.
- Outcome rows: `applied` has `reason` NULL; `rejected` has a non-empty `reason`.
- `applyPendingCommands` with a displaced or stale handle throws `LeaseLostError` and writes nothing. Processing order of pending commands is not part of the contract.

CLI output for task commands (frozen 2026-11-10, Lead): on exit 0 the first stdout line is exactly `created <commandId>` or `duplicate <commandId>` (ASCII), followed by an Arabic line. `init` stores `repo_path` as the absolute resolved path of `--repo` (compare by resolved filesystem identity, case-insensitive on Windows).
