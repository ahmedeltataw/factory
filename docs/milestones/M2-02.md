# M2-02: append-only command log

Status: local implementation card. Depends on the provisional M2-01 storage contract. The local branch is for continued work only; M2-01 and M2-02 remain unaccepted until required review, evidence and CI gates are satisfied. No GitHub upload or merge into `main` is authorized.

## Boundary

This card records commands only. It does not process commands, change domain state, perform effects, provide an ownership lease, or guarantee external exactly-once delivery. Those behaviors require later cards.

## Contract

Upgrade the existing SQLite database from user version 2 to 3 transactionally, preserving the `projects` table and its data. Fresh databases reach version 3. Add `commands` with columns `id`, `project_id`, `kind`, `payload_json`, and `created_at`; all are non-null TEXT. `id` is the primary key and `project_id` references `projects(id)` with delete restricted. SQLite must reject invalid JSON payloads and IDs, project IDs and kinds containing only ASCII whitespace (space, tab, line feed, carriage return, form feed or vertical tab), even when inserted directly. SQL triggers must prevent direct updates, deletes, and replacement of an existing command, including `INSERT OR REPLACE` when recursive triggers are disabled. A rejected or ignored write leaves existing data unchanged.

Export `appendCommand(db, command)` from `supervisor/src/app/commands.ts`. The input is `{ id: string, projectId: string, kind: string, payloadJson: string, createdAt: string }`. It returns `'created'` for the first insert and `'duplicate'` for an exact repeat. The whole input is validated using zod: IDs and kind are nonempty after trimming but are stored verbatim; `createdAt` must be the exact UTC form returned by `Date.prototype.toISOString()` and identify a real date; `payloadJson` must be valid JSON text. Compare all five stored fields exactly, including JSON whitespace and timestamp; same ID with different data throws `CommandConflictError`. Foreign-key or invalid-input errors throw without inserting. The method must work inside an existing caller transaction without beginning, committing or rolling it back; it must also work with no explicit transaction. Use a single atomic insert-or-ignore followed by an immutable-row comparison; do not use replace or alter existing commands. Simultaneous same-ID attempts on separate database connections must leave at most one row.

Builder scope: `supervisor/src/app/store.ts`, new `supervisor/src/app/commands.ts`, and new builder-owned tests outside `tests/protected/**`. Lead updates M2 store protected tests and the property test from version 2 to 3 because the current version changed; previous evidence remains tied to its recorded SHA. Builder cannot modify protected tests, documentation, package files, CI, or unrelated M1 files.

- `CHK-M2-02-a`: fresh and v2-upgrade migrations reach version 3 and preserve existing project data and previous schema invariants.
- `CHK-M2-02-b`: a valid new command is persisted and remains unchanged through reopen; exact duplicates return `duplicate` without creating another row.
- `CHK-M2-02-c`: differing fields for an existing ID raise `CommandConflictError`; invalid IDs, kind, JSON, timestamp or missing project never create a row.
- `CHK-M2-02-d`: direct SQL update/delete and direct invalid inserts are rejected; a caller rollback undoes a newly appended command.
- `CHK-M2-02-e`: competing connections attempting the same ID cannot create multiple rows; the actual concurrency test and any untested failure modes are recorded.
- `CHK-M2-02-f`: required local tests, typecheck, source guards, property and mutation checks pass and evidence records what was actually run. CI on Windows and Ubuntu, independent review and milestone acceptance remain separate gates.
