# M2-04: read-only status

Status: provisional local card, dependent on M2-03 storage schema. Do not merge into `main`, upload to GitHub, or claim CI/Claude review.

## Contract

Export synchronous `readStatus(stateDir, { nowMs, staleAfterMs })` and `formatStatus(status)` from `supervisor/src/app/status.ts`. `readStatus` opens `stateDir/state.sqlite` using SQLite's read-only mode, never calls `openStore`, never creates/migrates a database or changes rows, and always closes its connection. A missing, unreadable, corrupt or non-version-4 database and invalid numeric inputs must throw. `nowMs` is a nonnegative safe integer and `staleAfterMs` a positive safe integer.

Return `{ schemaVersion: 4, recordedCommandCount: number, lease: null | { ownerId: string, generation: number, heartbeatMs: number, state: 'active' | 'released', freshness: 'fresh' | 'stale' | 'future' | 'not-applicable' } }`. For active leases, `future` means heartbeat greater than now; otherwise `stale` begins when age is greater than or equal to `staleAfterMs`; otherwise `fresh`. Released leases always use `not-applicable`. Validate the row's fields and count rather than inventing defaults if data is malformed. A fresh heartbeat is not proof the process is alive. `recordedCommandCount` is not a pending count because command processing is not yet implemented. Do not return payloads or secrets. `formatStatus` produces clear Arabic human-readable text for the same facts, explicitly describing heartbeat freshness rather than claiming a process is running.

All database facts returned by one `readStatus` call must come from the same SQLite read snapshot even if a separate connection changes commands and the lease during the read. Use a read-only transaction and close the connection on every outcome. Never write or migrate domain data.

Implement `supervisor/src/cli/main.ts` as `factory status --state-dir <path> [--json]`. The only command is `status`; bad/missing/duplicate/unknown arguments return exit 2 and print an Arabic usage error to stderr without opening a database. Successful JSON is one parseable status object on stdout; default is the Arabic rendering. Status/read errors return exit 1 with a concise Arabic message on stderr. The CLI must not echo payloads. Build must keep the existing core entry and produce `lib/factory.mjs`, and `package.json` exposes it as `bin.factory`. Running `node lib/factory.mjs status ...` must work after `pnpm build`; do not rely on a globally installed tsx or other new runtime tool.

Lead-owned protected tests are `tests/protected/m2-status.spec.ts` and `tests/protected/m2-status-cli.spec.ts`. Builder scope: new `supervisor/src/app/status.ts`, new `supervisor/src/cli/main.ts`, `tsdown.config.ts`, `package.json` (bin only), and builder-owned tests outside `tests/protected/**`. No edits to store, lease, commands, protected tests, docs, dependency versions, lockfile, or CI. The Lead will independently run tests and review all changes.

- `CHK-M2-04-a`: status reads an existing version-4 DB, reports exact command count and lease values, and classifies absent, fresh, stale, future and released lease cases correctly.
- `CHK-M2-04-b`: missing DB, unsupported version, invalid inputs and malformed DB fail without creating or modifying database contents.
- `CHK-M2-04-c`: Arabic and JSON views represent the same facts without claiming a fresh heartbeat proves a live process or exposing payloads.
- `CHK-M2-04-d`: CLI argument errors are exit 2; read failures are exit 1; success is exit 0; built CLI and core build both exist and work.
- `CHK-M2-04-e`: local verification, required property/mutation coverage where applicable, evidence, independent review, Linux/Windows CI and milestone acceptance remain separate; do not report unrun checks as passed.
