### Scope (pure module `supervisor/src/core/scope.ts`, no I/O, no imports outside `core/`)

- `parseScope(input: unknown): { ok: true; scope: string[] } | { ok: false; reason: string }`. Input is an array of 1..32 strings. Each entry: 1..200 characters, printable ASCII only (U+0020–U+007E; anything else, including control characters and all non-ASCII, is rejected), no `~` (8.3 short-name aliases), no `\`, no `:`, no glob characters `* ? [ ]`, does not start with `/`, does not end with `/`; split on `/` gives no empty segment, no `.` or `..` segment, no segment that starts with a space or ends with a space or `.` (Windows trailing dot/space aliases), no segment that is a Windows reserved device name (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`, ASCII case-insensitive) on its own or followed by `.` and anything (`nul.txt`, `Com1.tar.gz`), and no segment equal to `.git` (ASCII case-insensitive). Lead amendment 2026-11-10 after M4-02 review: ASCII-only and the `~`/trailing-dot/space rules close Windows aliasing (Unicode case folding, 8.3 names, `a.` = `a`), so ASCII case-insensitive overlap is complete. The single entry `.` means the whole repository. Output: entries deduplicated and sorted (code-unit order); if any entry is `.`, the output is exactly `["."]`; an entry covered by another entry (`a` covers `a/b`; case-sensitive, so `a` does not cover `A/b`) is removed.
- `scopesOverlap(a: string[], b: string[]): boolean`: true when some entry of `a` and some entry of `b` are equal, or one is a path prefix of the other at a `/` boundary, or either is `.`. Comparison is ASCII case-insensitive (conservative: Windows file systems are case-insensitive).
- `pathInScope(path: string, scope: string[]): boolean`: `path` is a repo-relative git path with `/` separators. True when scope is `["."]`, or `path` equals an entry, or starts with `entry + '/'`. Comparison is case-sensitive (strict: git paths are case-sensitive).

### Commands and CLI (exit codes 0/1/2 and Arabic messages as in M3; first stdout line `created <id>` / `duplicate <id>` unchanged)

- `factory task create --state-dir <d> --title <t> [--scope <path>]... [--max-attempts <1..10>] [--timeout-ms <1000..86400000>] [--command-id <uuid>]`. `--scope` is repeatable; omitted → `["."]`. The CLI validates with `parseScope` (invalid → exit 2, Arabic usage, nothing written) and stores the payload `{ "title": string, "scope": string[], "maxAttempts": int, "timeoutMs": int | null }` with the normalized scope and defaults filled in (`maxAttempts` 3, `timeoutMs` null). Duplicate detection compares this normalized payload.
- `factory task retry --state-dir <d> --task <id> [--command-id <uuid>]` → command kind `task.retry`, payload `{ "taskId": string }`.
- Apply `task.create`: validates the payload again (`parseScope`, ranges); invalid → `rejected`. A legacy M3 payload `{ "title" }` with no other keys is accepted with the defaults. Writes `scope_json` (normalized JSON array), `max_attempts`, `timeout_ms`.
- Apply `task.retry`: task in `failed` → status `ready`, `attempt_base` = the task's current `MAX(attempt_no)` (0 if none), `not_before_ms` = 0, outcome `applied`. Any other status or unknown task → `rejected` (a `dropped` task is final, M3 rule).

### Retry, timeout and backoff semantics (Supervisor loop)

- Attempt budget: a task may start attempt number `n` only if `n - attempt_base <= max_attempts`; otherwise the task becomes `failed`. This replaces the M3 constant `MAX_ATTEMPTS` (default `max_attempts` 3 keeps M3 behaviour).
- Executor exit code `75` (`EX_TEMPFAIL`) is retryable: attempt `failed`, `error_class` `transient`, no evidence. Any other non-zero exit stays final as in M3, with `error_class` `exit`.
- Retry backoff: after a `transient` or `timeout` attempt, if the budget allows another attempt, the task returns to `ready` with `not_before_ms = nowMs + min(RETRY_BASE_MS * 2^(k-1), RETRY_MAX_MS)`, where `k` = number of attempts since `attempt_base`; `RETRY_BASE_MS` = 1000, `RETRY_MAX_MS` = 60000 (exported from `recovery.ts`). Budget exhausted → task `failed`. `interrupted` attempts after a Supervisor crash keep M3 behaviour (re-attempt at once, bounded by the budget).
- Dispatch only schedules `ready` tasks with `not_before_ms <= nowMs`. A `ready` task waiting for its backoff keeps the Supervisor from idling (`--exit-when-idle` waits for it).
- Spawn passes env `FACTORY_ATTEMPT_NO=<attempt_no>` (the absolute attempt number) to the executor.
- Timeout: when a worker becomes `running`, `attempts.deadline_ms` = spawn time + `timeout_ms` (NULL when `timeout_ms` is NULL). In the worker-liveness phase, an alive worker with `nowMs >= deadline_ms` is killed with `killTree`: `killed` → worker `killed`; `not-running` → normal completion handling (`result.json`) instead; `identity-mismatch` → worker `lost`; `kill-failed` → retried next tick, nothing changed. The timed-out attempt becomes `interrupted` with `error_class` `timeout`, then the retry rule above. Deadlines are wall-clock values in the DB, so they survive a Supervisor restart.
- Outbox backoff: on handler error `next_attempt_ms = nowMs + min(BACKOFF_MS * 2^(tries-1), OUTBOX_BACKOFF_MAX_MS)` with the new `tries`; `BACKOFF_MS` 1000, `OUTBOX_BACKOFF_MAX_MS` 30000, `MAX_TRIES` 3 unchanged.
- `SQLITE_BUSY`: a tick that fails with SQLite busy/locked (`errcode` 5 or 6) is not fatal. `factory start` logs one Arabic line to stderr, keeps the lease handle, and runs the next tick after the heartbeat interval. `LeaseLostError` stays fatal (exit 1). Every effect of the failed tick is either committed or rolled back as a unit per `fencedWrite`; nothing is half-applied.

### Scope locks

- A task holds its scope from dispatch (status `progress`) until it leaves `progress`. Lock state is derived from the DB (`tasks.status`, `tasks.scope_json`), so it survives restart with no extra table.
- Dispatch order: `ready` tasks by `created_at`, then `rowid`. `held` starts as the scopes of all `progress` tasks. For each ready task in order: if `scopesOverlap(task.scope, held)` → skip (the task stays `ready`); else if `not_before_ms <= nowMs` → schedule it. In both cases (skipped, or waiting for backoff, or scheduled) add its scope to `held`, so a later task never overtakes an earlier task whose scope it overlaps (FIFO, no starvation).
- Reconcile after a crash re-schedules an interrupted task at once (M3) without a lock check: the task never released its scope.
- Enforcement before commit: the `evidence.commit` effect lists every changed path in the worktree (tracked changes and untracked files, `git status --porcelain=v1 -z --untracked-files=all`, rename sources and targets both counted). If any path fails `pathInScope`, no commit and no evidence are made; the attempt becomes `failed` with `error_class` `scope-violation`, the task `failed` (final, not retried), and the outbox row `done` with `last_error` `scope-violation: <first bad path>`. The dirty worktree is reset before any later reuse (M3-03 rule).

### Fake executor scenarios (env read by `supervisor/src/executors/fake-executor.ts`, in addition to M3 `FAKE_SLEEP_MS` / `FAKE_EXIT_CODE`)

- `FACTORY_ATTEMPT_NO` (set by the Supervisor; missing → 1).
- `FAKE_FAIL_UNTIL_ATTEMPT=<n>`: when `FACTORY_ATTEMPT_NO <= n`, write `result.json` with `FAKE_FAIL_CODE` (default 75) and exit with it, writing no output file.
- `FAKE_HANG=1`: after `worker.json` and the grandchild, never exit and never write `result.json` (until killed).
- `FAKE_WRITE=<p1>,<p2>,...`: also write these repo-relative files (deterministic content) in cwd. An absolute path, a `..` segment, or a path resolving outside cwd → exit 2 without writing anything.
- Precedence: `FAKE_HANG` > `FAKE_FAIL_UNTIL_ATTEMPT` > `FAKE_EXIT_CODE` > normal. Invalid numbers → exit 2. The executor still touches nothing outside cwd and its run dir.

### Status additions (`--json`; Arabic view shows the same facts)

- Each task adds `scope: string[]`, `maxAttempts`, `timeoutMs` (number or null), `notBeforeMs`, `blockedBy: string[]` (ids of `progress` tasks whose scope overlaps this `ready` task; `[]` otherwise). Each attempt adds `errorClass` (string or null) and `deadlineMs` (number or null).
- `outbox` adds `failedRows: [{ key, kind, tries, lastError }]`.
- `factory status ... --watch [--interval-ms <200..60000>] [--count <n>]`: prints a snapshot every interval (default 2000) until interrupted, or `n` snapshots. With `--json` each snapshot is one line (NDJSON). Each snapshot is its own read-only transaction; status never writes.
