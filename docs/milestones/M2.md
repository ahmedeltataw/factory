### M2-01 SQLite migration foundation · Builder A · risk high

Builder scope: `supervisor/src/app/store.ts` and new builder-owned tests outside `tests/protected/**`. Lead-owned protected contract: `tests/protected/m2-store.spec.ts`. No edits to existing protected tests, the manifest, or imported M1 files. No network, GitHub, git changes, package changes or dependencies.

Implement synchronous `openStore(path: string): DatabaseSync` in `supervisor/src/app/store.ts`, using `node:sqlite`. The caller owns and closes the returned connection. A failed open or migration must close its connection and throw; never replace, delete or silently reset the database. Each open enables foreign keys and a 5000 ms busy timeout. File-backed databases must use WAL; if WAL cannot be enabled, fail rather than silently downgrade. In-memory databases cannot satisfy the WAL requirement and are rejected.

Use `PRAGMA user_version` as the schema version. Version 1 contains `projects(id TEXT PRIMARY KEY NOT NULL, name TEXT NOT NULL, created_at TEXT NOT NULL)`. Version 2 adds the index `projects_name_idx` on `projects(name)`. A fresh database reaches version 2; a version-1 database is upgraded to 2 preserving existing data. Migration from 0 to 2, and each upgrade, must be atomic: a failure leaves the database at its original version and without partial changes. Reject unsupported future versions without modifying their data. Check the version again after acquiring the migration write transaction, so a concurrent upgrade cannot be returned as a supported database. This is a small foundation, not the final domain schema.
